# YOLO11 Document OCR Pipeline

A clean, production-grade module for fine-tuning **YOLO11** (via Ultralytics) as a 2D spatial character detector on synthetic document pages, designed to benchmark directly against the **CRNN** pipeline on identical content generated by `synth_pages`.

---

## 1. Architectural Philosophy: CRNN vs. YOLO11

This project compares two fundamentally distinct computer vision paradigms for document transcription:

| Aspect | CRNN Pipeline (`crnn/`) | YOLO11 Pipeline (`yolo/`) |
|---|---|---|
| **Input Representation** | 1D rectified line crops (height 48 px, variable width) | Full page image (1024 px wide, 160–1024 px tall) |
| **Model Type** | Hybrid CNN + 2-layer Stacked BiLSTM | Ultralytics YOLO11 (`yolo11n.pt` to `yolo11x.pt`) |
| **Prediction Target** | 1D sequence alignment via CTC loss | 2D bounding boxes + class per character |
| **Alphabet / Classes** | 73 glyphs + space (`' '`) + CTC blank (75 classes) | **73 non-space character classes** (IDs 0–72) |
| **Space Handling** | Learned explicitly as index 73 in vocabulary | Reconstructed geometrically from inter-box gaps |
| **Layout Dependency** | Requires pre-segmented text line crops | Detects characters anywhere on the raw document page |
| **Evaluation Metrics** | Strict CER, Normalized CER, WER, Sequence Accuracy | **mAP50, mAP50-95** PLUS **Strict CER, Normalized CER, WER** |

## 3. What YOLO Detects & How Reading Order is Reconstructed

### Detection Unit: 73 Non-Space Character Classes
- Lowercase: `a-z` (IDs 0 to 25)
- Uppercase: `A-Z` (IDs 26 to 51)
- Digits: `0-9` (IDs 52 to 61)
- Punctuation: `.` `,` `;` `:` `!` `?` `'` `"` `-` `(` `)` (IDs 62 to 72)

### Text Reconstruction from 2D Boxes (`postprocess.py`):
1. **Vertical Line Grouping**: Detected character boxes are clustered into text lines using vertical overlap tolerance (`line_grouping_tol=0.6`).
2. **Left-to-Right Sorting**: Characters within each line are ordered by horizontal position (`cx` ascending).
3. **Spatial Gap Space Insertion**: Because space is not a visual glyph, a space `' '` is inserted whenever the gap between adjacent boxes exceeds `space_gap_ratio * median_char_width`.
4. **Normalized CER Evaluation**: To account for visual look-alike ambiguity in random Latin text, CER is measured both strictly and normalized across canonical equivalence groups (`I/l/1`, `O/0/o`, `c/C`, `s/S`, `v/V`, `w/W`, `x/X`, `z/Z`).

## 4. Quick Start

### Step 1: Install Dependencies
```bash
pip install -r yolo/requirements.txt
```

### Step 2: Prepare and Verify the YOLO Dataset
Generate the dynamic `data.yaml` and verify label coordinates and class ranges:
```bash
python -m yolo.dataset --config yolo/training.yaml --verify
```

### Step 3: Train / Fine-tune YOLO11

**Train from default pretrained YOLO11 model (`yolo11n.pt`):**
```bash
python -m yolo.train --config yolo/training.yaml
```

**Fine-tune from a specific pretrained model or checkpoint:**
```bash
python -m yolo.train --config yolo/training.yaml --model_path yolo11s.pt --epochs 40 --batch_size 16
```

**Resume an interrupted training run:**
```bash
python -m yolo.train --config yolo/training.yaml --resume
```

## 5. Benchmark Evaluation (Direct CRNN Comparison)

Run `yolo.evaluate` to measure both **Object Detection mAP** and **End-to-End OCR Transcription Error Rates** on all test splits:

```bash
python -m yolo.evaluate \
  --config yolo/training.yaml \
  --weights yolo/checkpoints/yolo11_best.pt
```

## 7. Critical Pitfalls & Augmentation Rules for Document OCR

1. **Horizontal/Vertical Flips MUST be 0.0 (`fliplr=0.0`, `flipud=0.0`)**:
   Mirroring letters changes their identity (e.g. `b` becomes `d`, `p` becomes `q`).
2. **Use Native Resolution (`imgsz=1024`)**:
   Punctuation marks (periods, commas) can be only 3–4 px tall on a 1024 px page. Downscaling destroys them.
3. **Mosaic & Mixup Disabled (`mosaic=0.0`, `mixup=0.0`)**:
   Mosaic distorts paragraph structures and alters spatial reading order.
4. **Dynamic Paths in `data.yaml`**:
   `synth_pages` writes an absolute path at generation time. `yolo.dataset` dynamically resolves `data.yaml` to ensure portability across local machines and Kaggle.
